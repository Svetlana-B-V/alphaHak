## 📌 Часть 1. Что такое GitHub и зачем он нужен

**GitHub** — это платформа для хранения кода и совместной работы команды.

### Основные понятия простыми словами:

| Термин | Что это простыми словами |
|--------|-------------------------|
| **Репозиторий** | Папка с проектом в облаке (как Google Drive, но для кода) |
| **Коммит** | "Сохранение" изменений с описанием, что сделано |
| **Ветка (branch)** | Копия проекта для экспериментов (не ломает основную версию) |
| **Pull Request (PR)** | Запрос на добавление изменений в основную версию |
| **Main/Master** | Главная ветка — рабочая версия проекта |
| **Push** | Отправить изменения из компьютера в облако |
| **Pull** | Скачать изменения из облака в компьютер |
| **Merge** | Объединить изменения из ветки в основную версию |

## 📌 Часть 3. Как запустить проект (пошагово)

### Шаг 1. Установить Node.js

1. Перейти на https://nodejs.org
2. Скачать версию **LTS** (рекомендуемую)
3. Установить (как обычную программу)
4. Проверить: открыть терминал (PowerShell на Windows) и написать:
   ```bash
   node -v
   ```
   Должно показать что-то вроде `v20.10.0`

### Шаг 2. Установить Git

1. Перейти на https://git-scm.com/downloads
2. Скачать и установить
3. Проверить:
   ```bash
   git --version
   ```

### Шаг 3. Клонировать репозиторий

```bash
# Перейти в папку, где будет проект
cd C:\Users\Svetik\Desktop\ProjestsGit

# Клонировать (один раз)
git clone https://github.com/ВАШ_ЛОГИН/alphaHak.git

# Войти в папку проекта
cd alphaHak
```

### Шаг 4. Установить зависимости

```bash
npm install
```

Это скачает все нужные библиотеки (один раз, занимает 1-2 минуты).

### Шаг 5. Запустить проект

```bash
npm run dev
```

В терминале появится:
```

➜  Local:   http://localhost:5173/
```

Открыть в браузере: **http://localhost:5173/**

### Шаг 6. Остановить проект

В терминале нажать **Ctrl + C**

## 📌 Часть 5. Как делать коммиты (сохранять изменения)

### Базовый workflow

```bash
# 1. Посмотреть, что изменилось
git status

# 2. Добавить все изменения
git add .

# 3. Сделать коммит с описанием
git commit -m "Описание того, что сделано"

# 4. Отправить в GitHub
git push
```

### Формат хороших коммитов

Используем стандарт **Conventional Commits**:

| Префикс | Когда использовать | Пример |
|---------|-------------------|--------|
| `feat:` | Новая функция | `feat: добавить страницу дашборда` |
| `fix:` | Исправление ошибки | `fix: исправить цвет кнопки` |
| `docs:` | Изменения в документации | `docs: обновить README` |
| `style:` | Изменения в стилях | `style: изменить отступы в Card` |
| `refactor:` | Рефакторинг кода | `refactor: упростить Button` |
| `test:` | Добавление тестов | `test: добавить тесты для Badge` |
| `chore:` | Технические изменения | `chore: обновить зависимости` |

### Примеры хороших коммитов

```bash
# ✅ Хорошо
git commit -m "feat: добавить компонент Input для форм"
git commit -m "fix: исправить выравнивание в Card"
git commit -m "docs: обновить инструкцию по запуску"

# ❌ Плохо
git commit -m "поправки"
git commit -m "update"
git commit -m "123"
```

## 📌 Часть 6. Как работать с ветками (для командной разработки)

### Зачем нужны ветки?

Каждый разработчик работает в своей ветке, чтобы не мешать другим. Когда работа готова — изменения объединяются в основную ветку через Pull Request.

### Workflow для команды

```bash
# 1. Обновить main до актуальной версии
git checkout main
git pull

# 2. Создать новую ветку для задачи
git checkout -b feature/dashboard-page

# 3. Работать, делать коммиты
# ... работа ...
git add .
git commit -m "feat: добавить страницу дашборда"

# 4. Отправить ветку в GitHub
git push origin feature/dashboard-page

# 5. На GitHub создать Pull Request (через интерфейс)

# 6. После ревью — смержить в main
```

### Именование веток

| Тип ветки | Формат | Пример |
|-----------|--------|--------|
| Новая функция | `feature/название` | `feature/dashboard-charts` |
| Исправление | `fix/название` | `fix/button-alignment` |
| Документация | `docs/название` | `docs/update-readme` |
| Релиз | `release/версия` | `release/v0.2.0` |

## 📌 Часть 10. Шпаргалка команд Git

### Базовые команды

```bash
git status              # Посмотреть, что изменилось
git add .               # Добавить все изменения
git add filename        # Добавить конкретный файл
git commit -m "msg"     # Сделать коммит
git push                # Отправить в GitHub
git pull                # Скачать изменения из GitHub
```

### Работа с ветками

```bash
git branch              # Список веток
git checkout main       # Переключиться на main
git checkout -b name    # Создать новую ветку и переключиться
git merge branch-name   # Объединить ветку с текущей
```

### Полезные команды

```bash
git log                 # История коммитов
git log --oneline       # Краткая история коммитов
git diff                # Посмотреть изменения
git stash               # Временно сохранить изменения
git stash pop           # Вернуть сохранённые изменения
```

### Отмена изменений

```bash
git checkout -- file    # Отменить изменения в файле
git reset HEAD file     # Убрать файл из индекса
git reset --soft HEAD~1 # Отменить последний коммит (сохранить изменения)
git reset --hard HEAD~1 # Отменить последний коммит (УДАЛИТЬ изменения!)
```
